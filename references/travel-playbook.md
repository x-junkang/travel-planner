# 旅行查询与交付手册

用于查询字段、报价记录、攻略结构及交付检查。按当前任务阅读相关部分；不为填满模板添加无关内容。

## 1. 查询条件与来源

在查询前确定报价对应的出发地、目的地、出行日期、旅客人数和年龄类别、舱等/席别，以及酒店入住退房日期、入住人数、房间数与床型。用户仍有弹性时，明确每组候选方案的假设，避免交叉使用不同日期的价格。

按核心流程先检查携程登录。用户完成登录后，从当前页面重新确认日期、人数、房间数与产品条件，再读取报价；不能沿用登录前的筛选假设。空白、加载失败或无结果不等于未登录或无库存，应先区分页面故障、认证要求及明确的无房/无票提示。

优先查询携程；车次与铁路规则按需核对 12306，航班与行李要求按需核对承运航司，酒店入住与设施按需核对酒店官网，景点开放及预约按需核对官方渠道。评论可以辅助判断噪音、位置和体验，不能证明当前库存或营业时间。地图路线优先使用可访问的路线规划来源；无法获取时标为估算，不以直线距离声称实际交通耗时。

每条报价应记录以下信息，可直接存在攻略对应表格及其备注中，无须另建数据库：

| 字段 | 记录要求 |
| --- | --- |
| 产品及条件 | 班次/酒店、日期、旅客或房间条件、席别/房型、套餐 |
| 时间和位置 | 出发/到达或入住/退房，当地时区，准确站点或酒店地址/区域 |
| 金额 | 币种、每人/每程/每间每晚等计价单位、全段合计，含税费情况 |
| 关键限制 | 行李、早餐、取消/退改、儿童入住、额外费用等已查到的条件 |
| 优惠资格 | 会员、旅客地区、设备或支付方式限制，以及用户是否已确认符合；无需记录身份号码或账户详情 |
| 核验信息 | 页面查询报价/参考估算/待核实，实际查询日期时间及其时区 |
| 依据 | 来源名称与实际访问的链接；估算应说明依据和计算假设 |

无法确认的字段写“待核实”，不能默认为免费、含税、含早或可取消。报价总额已含税费时不再重复加税；只看到基础价格时明确还有费用待核实。

使用可分享的实际产品或搜索结果链接；若深层链接失效、含敏感会话参数或无法复现，提供经过核验的公开入口并写明产品名称和搜索条件，注明需要重新搜索。不要虚构直达预订 URL，也不要把个人订单、账户信息或凭据写入攻略。

### 境外重点比价

保留携程作为基准，对首选航班及每个住宿落脚点的首选酒店，再尝试一至两个适用的国际平台或官网，不默认对全部候选全面比价。酒店可选 Booking.com、Agoda 或酒店官网；机票可用 Skyscanner 发现选项，再核对实际售票方的产品、价格与条件。来源随目的地和可访问能力选择，不承诺某个平台一定有库存或更便宜。

- 酒店先核对同一分店、入住/退房日期、实际人数与年龄、房间数、房型、床型、早餐及取消条件；航班先核对实际人数、日期、班次、席别/票价产品、行李与退改条件。
- 展示含税费总价；税费未知时注明不能直接比较。保留原币金额，按注明日期和来源的汇率给出统一币种参考价，不能把换算值说成平台实际结算价。
- 条件一致才比较总价并说明价差；房型、行李或取消政策不同则作为不同产品解释取舍，不能仅按低价排名。会员、地区、设备或支付方式优惠单独标注；用户资格不明时不纳入可用最低价。
- 聚合搜索显示的报价若未在实际售票方核验，标为该来源展示价及待核验条件，不当作已确认的可订报价。某平台显示无房或无票时明确平台和查询条件，不能扩大成酒店或航班全部售罄；独立查询其他来源，保留各自结论。
- 补充平台只有查询受限时才请求用户登录；主平台的登录等待不能被跨站查询替代。反复遇到相同阻碍且没有新信息时停止重试，记录未查来源和原因。仅称已查来源中的较优方案，不声称全网最低价。

在交通和住宿各自的表格旁附简短比价表，字段为“产品与查询条件｜平台/售票方｜原币含税总价｜统一币种参考价｜条件差异与优惠资格｜查询时间、状态和来源”。无可比报价时说明缺口，不为填表虚构金额。

## 2. 交通、住宿与路线选择

### 大交通

对往返和城市间各段分别比较首选及有意义的备选，给出日期、班次、站点、当地出发/到达时间、时长、席别、价格与条件。联程和自行中转需区分；计入换航站楼/车站、行李提取与重新托运等实际需要，不能只比较两段票面时刻。

优先按实际成人和儿童人数、年龄类别查询并读取全员总价。若页面仅提供单人价，保留该查询条件；乘人数所得金额标为推算，说明多人同价与库存尚未核验，不称作已查询到的全员报价。

选择理由围绕用户关心的成本、总耗时、出发时间、换乘负担及舒适度。考虑市区到机场/车站以及抵达后到酒店的交通成本；缓冲时间结合交通方式、机场车站要求与实际环境，不统一套用固定分钟数。晚间到达时核对末班车和酒店可入住时间，早班出发时检查酒店到站路线。

未开售：明确当前无法确认指定日期库存及价格；如果能核验开售规则，给出预计可查询日期及其依据。已售罄：查邻近时间、其他交通方式或日期备选，并说明用户需接受的变化。不能悄悄替换用户不可调整的日期。

### 酒店

先按交通节点、游览区域、夜间环境和预算选住宿区域，再给具体酒店。每个落脚点通常推荐两至三家，写明首选理由及实际缺点，不能仅凭星级或宣传文案排序。核对同名酒店的具体分店。

包含入住/退房日期、晚数、人数和儿童年龄条件、房间数、房型与床型、每晚价格和全程总额。价格逐晚变化时列逐晚金额或全程总价及平均每晚价格，不能把某一晚的最低价乘晚数。家庭入住核验容纳人数、加床及早餐儿童政策；查不到则标为待核实。

同条件比较早餐、税费和取消截止时间，取消时间带当地时区。尽量给出到主要交通节点或景点的交通方式及耗时，而不只说“位置好”。房型无库存时，其他房型或其他酒店作为单独备选，不能沿用原报价。

### 每日行程

按同一地理区域顺路组合景点，注明上午/下午/晚间、建议停留、下一段交通方式和时间。把抵离日可用时间、酒店入住退房、行李寄存、用餐及休息计入，避免到达即游览或游览结束立即发车的安排。

核验开放时间、闭馆日、最后入场、预约时间窗口与交通末班。雨天或高温替代方案优先选择同片区的室内活动；季节性风险与实际天气预报分开标记。自驾按需要加入取还车、停车和行驶时间及成本；不默认所有人都能驾驶。

境外旅行还需检查跨日、当地时区、交通运营日和跨境衔接。只有入境或过境问题影响线路时才补充所需的国籍/证件类型等信息，不收集证件号码；以官方当前要求为依据。

### 主要景点介绍卡片

每日行程表负责时间和交通，卡片帮助用户决定是否值得去、到达后怎么玩。每个主要景点用一小段具体介绍加简短要点；顺路市场、散步点适当缩短，不为凑字数添加历史背景或宣传文案。

| 内容 | 写法 |
| --- | --- |
| 名称与入口 | 中文名称及可核验的当地名称，附官方或地图链接；当地名称查不到不自行编造 |
| 看点与推荐理由 | 说明独特景观或体验，以及为什么匹配本次兴趣和路线，避免只有“热门”“必打卡” |
| 建议玩法 | 写重点区域、具体体验或简短游览顺序；将来源支持的事实与自己的安排建议区分 |
| 时间与体力 | 给出建议停留时间、步行或台阶强度，以及对同行者的适配考虑 |
| 适用条件 | 说明天气、季节等影响，区分季节参考与实际预报；不要把个人体验偏好当事实 |
| 差异与替换 | 相似景点说明各自特色和是否值得都去；备选说明替换哪个项目及何时替换 |

门票、预约和开放信息与每日行程表互相引用，避免复制后产生冲突。同一景点不必每天重复介绍；卡片的停留时间、玩法和替代关系必须与行程安排一致。

## 3. 预算计算

- 明确预算范围：默认从出发地到返程的交通、住宿、景点门票、市内交通、餐饮和机动费用；用户已有付款项目列为“已付”，区分旅行总成本与尚需支付，避免重复加入。
- 只将选中方案纳入总计；备选方案单独展示差额，不把所有候选票、酒店相加。
- 交通按实际成人/儿童票价类别及段数计算；住宿按每种房型、每天、间数求和。已给“全程两间房合计”的价格不可再次乘房数或晚数。
- 门票按需要购票的人数计算；包车、出租车等按整车或整次计算并核对人数容量；餐饮可按人天估算。没有核验的儿童优惠不当作已确认费用。
- 统一预算币种后才能汇总，列汇率日期、来源与换算假设，不把参考汇率视为最终结算汇率。
- 机动费用在明确基数上计算，默认采用已计入项目小计的 10%，作为可调整的规划假设；用户指定储备额或比例时使用用户值。
- 对区间分别汇总上下限。全员总额除以实际出行人数可给“平均人均成本”，并注明仅为均摊，成人/儿童实际花费可能不同。
- 缺乏依据的费用列为“未计入：待核实”；存在此类项目时，总额标为“已计项目合计”，不能宣称为完整预算或已满足预算上限。对已有依据的参考估算则纳入估算区间并标注。

## 4. Markdown 攻略结构

按下面顺序组织；表格过宽时把政策和长链接放到对应条目的备注中。用户仅要求调整局部时更新相关部分，无须再次输出整篇聊天内容。

1. **行程概览与需求**：目的地、完整日期和天数/晚数、出发/返程地、人数、预算口径、偏好、已订约束、生成/更新时间及假设。说明当前是日期候选草案还是指定日期规划。
2. **推荐路线与取舍**：城市顺序、每晚住宿地点、关键交通段、推荐理由和主要待确认项。
3. **大交通方案**：每段首选和备选的日期/班次/站点/时刻/时长/价格/条件，推荐理由、接驳以及来源；境外首选附同条件比价及差异说明。
4. **住宿区域与具体酒店**：按落脚点分组，列日期、酒店、房型/人数/间数、位置、价格及取消等关键条件；境外每个落脚点的首选附跨站比价。
5. **每日行程**：建议使用“日期与时段｜活动与停留｜点间交通｜门票及预约｜备注”表格；每天标注住宿地点，给必要的替代安排。
6. **主要景点介绍**：按路线顺序组织实用卡片，覆盖主要景点与重要备选的看点、推荐理由、玩法、时间体力、天气季节条件及官方或地图链接。
7. **预算汇总**：使用“类别｜计算依据｜全员费用或区间｜已付/待付｜报价状态与未计费用”表格，列已计小计、机动费用、总额/区间和平均人均成本。
8. **预订行动清单**：按实际紧迫性排序，注明对象、对应行程、操作入口、核验过的预约/退改截止时间；未知截止时间写待核实，不制造抢订紧迫感。
9. **待确认事项与来源**：集中列出影响可行性的缺口和用户下一步；引用应同时靠近相关信息，本节不要成为唯一的来源汇集处。

每条关键信息可追溯到来源即可，不要求大量重复链接。聊天摘要补充每天的核心看点，不能只列景点名称，也不要掩盖关键待核实条件。预算和来源应以中文可读文字解释，避免用内部工具名称或技术状态代替旅行建议。

## 5. 交付前核对

| 检查 | 通过条件 |
| --- | --- |
| 登录与查询条件 | 正式查价前已检查携程登录；未登录已提示并等待，或用户已明确选择公开查询/跳过；登录后已重新确认日期、人数和房间等条件 |
| 日期与住宿 | 交通日期、每天日期及当地时区一致；每个需要住宿的夜晚有安排；夜车/夜航单独注明，不机械按天数减一订房 |
| 时间衔接 | 移动、入场、用餐、休息及候车/值机有时间；跨站/跨机场与深夜交通可行，不能满足的约束显式列出 |
| 报价对应 | 指定日期、人数、房型/席别、币种和计价单位匹配；有来源与真实查询时间；搜索起价未被当成确定报价 |
| 跨站比较 | 境外重点选项已尝试额外一至两个来源或注明阻碍；税费和产品差异清楚，优惠资格已确认或未计入可用最低价；多人推算与实查价可区分 |
| 景点介绍 | 每个主要景点有具体看点、理由和玩法，停留时间及体力要求与路线一致；相似景点的差异、备选替换条件清楚 |
| 酒店容量 | 房间数、床型和可住人数满足实际家庭组成；儿童、加床等未知政策已披露 |
| 预算 | 只计首选，人数/间数/晚数与税费不重复；已付费用不重复；估算与未计费用可识别，算术正确 |
| 可用性 | 闭馆、预约、未开售与售罄已分别处理；备选变化清楚；查询受阻没有被掩饰为已核验 |
| 修订一致性 | 用户修改日期、人数或路线后，关联交通、酒店、时长和预算同步更新；未复查内容不继承新的查询时间 |

若某项未通过，先修正；受外部信息或用户未定事项限制而无法修正时，标为待确认并说明具体影响。携程登录请求未得到回复时，可提供路线草案但不作为完整攻略结束任务；用户明确选择公开报价或跳过后，按其选择交付其余可用内容。
